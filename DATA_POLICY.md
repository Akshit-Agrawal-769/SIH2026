# INCOIS 3D Ocean Data System — Data Policy

**Problem statement:** Smart India Hackathon (SIH 2026) — PS 26067

## 1. Principles

1. **Authentic sources only.** Gridded fields come from INCOIS Bio-ROMS (DOI
   10.5281/zenodo.13802393) and CMEMS ARMOR3D; observations come from the Argo GDAC.
   See `frontend/public/api/catalog.json` → `sources` for the exact files and products.
2. **No synthetic values.** Nothing in the served data is generated by a formula or random
   number generator. Missing, land or QC-failed values stay NaN (tiles) or `null` (JSON),
   and the API/UI report "no data" explicitly. The build script exits if a source file is
   missing.
3. **Argo quality control.** Only QC flags **1 (good)** and **2 (probably good)** are kept;
   flags 3, 4, 8, 9 are rejected. Adjusted values are used for parameters in A/D data mode.
   Profile time and position must also be QC 1/2.
4. **Depth from pressure.** TEOS-10 `gsw.z_from_p(p, latitude)`.
5. **Time.** Every timestamp shown comes from the source files. The timeline never
   interpolates between timesteps.

## 2. Provenance

`scripts/build_authentic_dataset.py` records, for every served artefact, the source file,
product/DOI, variable, unit conversion and regridding method in `api/catalog.json`, and the
QC policy, data modes and source file for every Argo profile in its metadata.

## 3. What was removed in the 2026-09 audit

Earlier releases served procedurally generated "ROMS" fields for 2024-06-01..05 at eight
depths, fabricated glider and moored-buoy profiles, and formula-based oxygen/chlorophyll for
two floats. These were deleted; see `AUDIT_REPORT.md`.
