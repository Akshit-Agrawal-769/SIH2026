# Ocean Data Standards & Interoperability Specification

This document details the data standards, metadata conventions, and geospatial web service interfaces implemented in the INCOIS 3D Ocean Data Visualization Platform to ensure interoperability with national and international oceanographic portals, GIS software, and scientific computing environments.

---

## 1. Climate and Forecast (CF-1.8) Metadata Conventions

All NetCDF-4 export datasets generated by the platform (`/api/export/netcdf`) strictly comply with the **CF Metadata Conventions Version 1.8**.

### 1.1 Global Attributes
| Attribute | Example Value | Description |
|---|---|---|
| `Conventions` | `CF-1.8` | Declares conformance with CF-1.8 metadata specification |
| `title` | `INCOIS 3D High-Resolution Numerical Ocean Model Output` | Human-readable title of the dataset |
| `institution` | `Indian National Centre for Ocean Information Services (INCOIS), MoES, Govt of India` | Responsible organization |
| `source` | `INCOIS Regional Ocean Modeling System (ROMS) with in-situ Argo/Moored Buoy assimilation` | Method of production |
| `references` | `https://incois.gov.in` | Authoritative documentation reference |
| `history` | `Exported on 2024-06-05T12:00:00Z via INCOIS 3D Web Visualization Platform` | Audit trail of creation |
| `geospatial_lat_min` / `max` | `-15.0` / `30.0` | Geographic bounds (North Indian Ocean) |
| `geospatial_lon_min` / `max` | `45.0` / `100.0` | Geographic bounds (Arabian Sea, Bay of Bengal, EEZ) |
| `geospatial_vertical_min` / `max` | `0.5` / `2000.0` | Depth column extent in meters |

### 1.2 Coordinate Variables
| Name | Dimension | Type | Standard Name | Units | Positive / Axis |
|---|---|---|---|---|---|
| `time` | `time` (1) | `float64` | `time` | `days since 2024-06-01 00:00:00` | `axis = "T"` |
| `depth` | `depth` (20) | `float32` | `depth` | `m` | `positive = "down"`, `axis = "Z"` |
| `latitude` | `latitude` (180)| `float32` | `latitude` | `degrees_north` | `axis = "Y"` |
| `longitude` | `longitude` (220)| `float32`| `longitude` | `degrees_east` | `axis = "X"` |

### 1.3 Physical Data Variables
| Variable Name | Shape | Standard Name (CF Table) | Units | Fill Value |
|---|---|---|---|---|
| `temperature` | `(time, depth, lat, lon)` | `sea_water_potential_temperature` | `degree_Celsius` | `-9999.0` |
| `salinity` | `(time, depth, lat, lon)` | `sea_water_practical_salinity` | `1` (PSU) | `-9999.0` |
| `currents` | `(time, depth, lat, lon)` | `sea_water_speed` | `m s-1` | `-9999.0` |
| `chlorophyll` | `(time, depth, lat, lon)` | `mass_concentration_of_chlorophyll_a_in_sea_water` | `mg m-3` | `-9999.0` |

### 1.4 Verification with Python (xarray)
```python
import xarray as xr

# Open exported file
ds = xr.open_dataset('INCOIS_temperature_2024-06-05.nc')

# Inspect CF-1.8 attributes
print(ds.Conventions)  # "CF-1.8"
print(ds.temperature.standard_name)  # "sea_water_potential_temperature"

# Calculate ocean thermal profile at 15°N, 68°E
profile = ds.temperature.sel(latitude=15.0, longitude=68.0, method='nearest')
profile.plot(y='depth', yincrease=False)
```

## 2. OGC Web Map Service (WMS 1.3.0 & 1.1.1)

The platform provides a standard Open Geospatial Consortium (OGC) Web Map Service endpoint allowing external desktop GIS (QGIS, ArcGIS), web map libraries (Leaflet, OpenLayers, MapLibre), and scientific tools to directly consume model layers.

### 2.1 Endpoint URL
- **Base Service URL**: `http://localhost:4000/api/wms`

### 2.2 Supported Operations
1. **`GetCapabilities`**:
   - URL: `http://localhost:4000/api/wms?SERVICE=WMS&REQUEST=GetCapabilities`
   - Returns standard XML detailing service identity, coordinate systems, bounding boxes, layers, time dimensions, and depth elevation values.

2. **`GetMap`**:
   - Renders georeferenced raster image tiles on-demand.
   - Example Request:
     ```http
     GET /api/wms?SERVICE=WMS&REQUEST=GetMap&LAYERS=temperature&BBOX=45,-15,100,30&WIDTH=512&HEIGHT=512&CRS=CRS:84&FORMAT=image/png&TIME=2024-06-05&ELEVATION=0.5&TRANSPARENT=TRUE
     ```
   - Parameters:
     - `LAYERS`: `temperature`, `salinity`, `currents`, `chlorophyll`
     - `BBOX`: `min_lon,min_lat,max_lon,max_lat` (or `min_lat,min_lon,max_lat,max_lon` for WMS 1.3.0 `EPSG:4326`)
     - `WIDTH` & `HEIGHT`: Image dimensions (32 to 2048 pixels)
     - `CRS` / `SRS`: `EPSG:4326`, `CRS:84`, `EPSG:3857`
     - `FORMAT`: `image/png`, `image/jpeg`
     - `TIME`: Date string (`2024-06-01` through `2024-06-14`)
     - `ELEVATION`: Depth in meters (`0.5` surface to `2000.0` abyss)
     - `TRANSPARENT`: `TRUE` (landmasses and NaNs are 100% transparent RGBA)

### 2.3 Desktop GIS Integration (QGIS)
To load INCOIS model layers into **QGIS**:
1. Open QGIS and go to `Layer -> Add Layer -> Add WMS/WMTS Layer...`.
2. Click **New** to create a new WMS connection:
   - **Name**: `INCOIS Ocean 3D Model WMS`
   - **URL**: `http://localhost:4000/api/wms`
3. Click **OK**, then click **Connect**.
4. Select any layer (e.g. `Ocean Potential Temperature`) and click **Add**.
5. Change the simulation date or depth elevation in the layer properties.
