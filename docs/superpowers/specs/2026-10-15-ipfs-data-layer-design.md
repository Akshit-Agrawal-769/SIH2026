# IPFS Data Layer (Meshkit0 + Kubo + Helia) — Design

**Date:** 2026-10-15 · **Branch:** `feat/ipfs-meshkit` · **Status:** approved in chat

## Goal

Serve WAVE's precomputed ocean tiles over IPFS as a third, content-verified data
source, so the app keeps working when the Render backend sleeps and every tile is
tamper-evident. Build it on the IPFS Meshkit SDK (`@ipfs-meshkit/meshkit`) and
measure it, so the result can be shown to the IPFS Meshkit lead as a grant-worthy
milestone.

## Current state

- `frontend/public/tiles/{variable}/{YYYY-MM-DD}/{depth}.bin` (~43 MB, 76 tiles,
  32-byte `INCO` header + Float32 520×280) and `frontend/public/api/*.json` ship
  inside the Vercel build, generated by `scripts/build_authentic_dataset.py`.
- The live data-service + gateway on Render build other months on demand from the
  9.2 GB INCOIS NetCDF on Hugging Face.
- `frontend/src/api/client.ts::loadTile()` tries the live API, then the static copy.

## Design

1. **Publish script** `scripts/ipfs/publish.mjs` (Node ≥ 20, own `package.json`):
   walks `frontend/public/tiles/` and `frontend/public/api/`, uploads and pins each
   file through `@ipfs-meshkit/meshkit` against a Kubo RPC API
   (default `http://127.0.0.1:5001`), and writes `frontend/public/ipfs-manifest.json`:
   `{ schema: "incois-ipfs-manifest/1", generated_at, generator, files: { "<posix path>": { cid, size } } }`.
2. **Kubo service** in `docker-compose.yml`: image `ipfs/kubo:v0.43.1`, RPC on
   `127.0.0.1:5001`, gateway on `127.0.0.1:8080`, named volume `ipfs_data`.
3. **Frontend IPFS source** `frontend/src/api/ipfsSource.ts`: loads the manifest
   (null if absent/invalid), maps a tile to its manifest path, and fetches by CID with
   `@helia/verified-fetch` (lazy-loaded), which hashes the bytes in the browser and
   rejects any that do not match the CID. Gateways from `VITE_IPFS_GATEWAYS`
   (comma-separated); default `https://trustless-gateway.link`, plus
   `http://127.0.0.1:8080` first in dev. Per-request timeout 8000 ms.
4. **Data-source mode** `auto | ipfs | server`, persisted in `localStorage` key
   `wave.dataSource` (default `auto`):
   - `server`: live API → static (today's behaviour)
   - `auto`: live API → IPFS → static
   - `ipfs`: IPFS → static
   Changing mode clears the tile cache.
5. **UI** `frontend/src/components/DataSourceBadge.tsx` (operational mode): shows
   the source of the last tile — `IPFS ✓ verified · <short CID>` / `Live API` /
   `Static (unverified)` — and a mode selector. Clicking the CID opens it on the public gateway.
6. **Benchmark** `scripts/ipfs/benchmark.mjs`: for N tiles from the manifest
   (default 12), fetch via (a) static HTTP, (b) local Kubo gateway, (c)
   verified-fetch through the public trustless gateway; record total ms, TTFB,
   success, and SHA-256 match against the local file; write
   `docs/IPFS_BENCHMARK.md` with median / p95 / success-rate per path.

## Revisions after research (2026-10-15 evening)

See `reports/IPFS stack and mentor profile 2.md` (research). Changes:
- **CIDv1 everywhere.** Kubo runs with `ipfs config profile apply unixfs-v1-2025`
  (CIDv1, raw leaves, 1 MiB chunks). The publish script fails if any CID starts with
  `Qm`. Each tile (< 1 MiB) must have the same CID from meshkit0, from a local
  `CID.create(1, raw, sha256)` and inside the directory root.
- **One root CID** for the whole published tree, plus per-file CIDs. Manifest:
  `{ schema, generated_at, generator, kubo_version, profile, git_commit, root,
  files: { path: { cid, size, sha256 } } }`, committed to Git as WAVE's pin list
  (ORCESTRA pattern).
- meshkit0 attaches to the Kubo service (`init({ nodes: [...] })`), never spawns
  one; `@ipfs-meshkit/meshkit` pinned to exactly `1.2.1`; Kubo RPC port 5001 is
  never exposed publicly.
- Badge says `IPFS ✓ verified` only for bytes that came through verified-fetch;
  otherwise `Live API` or `Static (unverified)`.
- Benchmark: cold and warm runs, ≥ 30 samples per path, p50/p95, date and gateway
  host stamped, verification overhead measured separately. Static hosting is
  expected to be fastest and the write-up says so.
- Upstream: a reproducible meshkit0 issue (CID version differs between Kubo and S3
  backends; propose a `cidVersion` option) and a small PR exporting
  `encrypt`/`decrypt`/`isEncryptedPayload` from the browser entry.
- Before publishing to public IPFS, the team confirms INCOIS / CMEMS terms allow
  redistributing the derived tiles.

## Out of scope

3D `volume3d` volumes (need pre-generation; milestone 2 with the AI bias-correction
model), removing Render, IPFS Cluster, IPNS.

## Constraints and honest limits

- Nothing existing is removed; static files remain the final fallback.
- Content is reachable only while some node pins it: for demos, also pin to a free
  pinning service; the laptop node alone goes offline when the laptop sleeps.
- `.ipfs/` and `scripts/ipfs/node_modules/` are git-ignored.

## Success criteria

- `npm run publish` in `scripts/ipfs` produces a manifest covering all 76 tiles and
  all 9 `api/**/*.json` files, each retrievable byte-identical from Kubo.
- With mode `ipfs`, the globe renders the same fields as today, the network panel
  shows CID fetches, and the badge reads `IPFS ✓ verified`.
- With no manifest, the app behaves exactly as on `main`.
- `docs/IPFS_BENCHMARK.md` exists with real measured numbers.
